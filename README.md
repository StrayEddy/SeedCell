# SeedCell

**🌐 Project site: [strayeddy.github.io/SeedCell](https://strayeddy.github.io/SeedCell/)**

**Autonomous public food infrastructure — the food sibling of [HiveCell](../HiveCell).**

> **Open-source hardware research — uncertified, not a deployable product.**
> SeedCell bakes and serves food to the public from an unattended machine. It is
> **design and simulation only**: no built hardware, no microbiological validation, no
> food-safety certification. **Do not build this to feed anyone.** See [`LICENSE`](LICENSE)
> for the full safety notice and licensing.

A public, autonomous machine that turns long-life dry ingredients into a fresh, warm,
nutritious flatbread on demand, so that **no one goes hungry because they cannot afford
food**. It is not a vending machine — it is closer to a **food syringe**: a sealed machine
that briefly opens, delivers food, then cleans itself.

Design priorities (in order): food safety & hygiene, vandal resistance, reliability, low
maintenance, low energy, low cost, simplicity, long lifetime. It guarantees basic
nutrition — a warm daily survival ration eaten by hand with no packaging — not a meal out.

## Mechanism

**The hot syringe (ADR-0001).** A single heated piston moves inside a fixed heated bore.
Idle, the piston face is the flush public wall. To make food it retracts to open a short
cook chamber; dry blend is metered in and **hydrated by injected water jets — no mixer
blade** (ADR-0006); the piston presses the dough and the two hot faces **conduction-bake**
it (ADR-0007); it advances to eject the flatbread through a fixed mouth die; then parks deep
in a sealed zone to **scrape + steam + heat-sterilize + dry** before the next serving
(ADR-0010). The whole cycle is one part translating along one axis — the same syringe bargain
as HiveCell.

The engineering goal is not making food — it is **minimizing food-contact surfaces**. The
design collapses them to essentially one chamber, one transfer, one delivery surface: the
bore wall, the piston face, and the die lip. Everything upstream stays dry (ADR-0012).

## Food

A fortified protein flatbread from whole-wheat + chickpea + lentil flour, a little oil, salt,
water, and a micronutrient premix. Target per serving (`scripts/dosing.py`, first-order):

| Metric | Target | Model |
|--------|--------|------:|
| Energy | 500–700 kcal | ~571 kcal |
| Protein | 20–30 g | ~26 g |
| Ingredient cost | $0.15–0.25 | ~$0.21 |

Cook thermodynamics + energy in `scripts/cook_energy.py` (~59 Wh/serving bake).

## Safety status

SeedCell makes food for **vulnerable people, unattended, for years**, so food safety is the
first design constraint. Full analysis in [`docs/SAFETY.md`](docs/SAFETY.md); decisions in
[`docs/DECISIONS.md`](docs/DECISIONS.md). The core invariant: **a batch that is not provably
cooked AND served on a provably clean surface is diverted to waste, never to a person.**

Current state — **design + simulation / first-order analysis, no certified hardware:**

| Safety function | Status |
|-----------------|--------|
| SF1 Cook lethality (primary) | diverse-redundant fail-safe voter (2× core probe + IR + F-value), serve only on positive proof (ADR-0009) — `[sim]` |
| SF2 Surface sanitation (primary) | scrape + steam + reused-heat sterilize + dry, verify-or-lockout every cycle (ADR-0010) — `[sim/decision]` |
| SF3 Contamination barrier / scraper seal | circular scraper lips wipe the full bore each stroke; drag/residue budget (ADR-0011) — `[cad]` |
| SF4 Burn + pinch guard | touch-safe surface cap + mouth force cap → abort present (H4/H5) — `[sim]` |
| SF5 Motion signalling + soft profile | beacon + soft-start/stop + slow final approach (shared with HiveCell) — `[sim]` |
| SF6 Ingredient integrity / spoilage lockout | dry-storage moisture/temp lockout (ADR-0012) — `[decision]` |

**Biggest open risk:** food **residue + release** is the master variable — it couples the
cleaning method (SF2), the scraper (SF3), the surface + formula (ADR-0008), yet is only
estimated (~1000× range, `scripts/residue.py`). It must be measured on a real baked coupon
before the cleaning design is frozen (ADR-0011). A ~$150–250 bench procedure to do exactly
that — the highest-value next experiment, and a great first contribution — is in
[`docs/residue_bench_test.md`](docs/residue_bench_test.md).

## Setup

The machine must never serve food that isn't provably safe, so the serve cycle is gated by a
food-safety interlock (`godot/process_interlock.gd`, per `docs/SAFETY.md`). A headless
self-test enforces the core invariant — a raw or unclean batch is never served — and a
pre-push hook blocks pushes if it fails.

After cloning, point git at the hook once:
```sh
git config core.hooksPath .githooks
```
Run the self-tests manually anytime (set `GODOT_BIN` if Godot isn't on `PATH`):
```sh
./scripts/run_selftest.sh
```
Regenerate the CAD model / run the analysis:
```sh
flatpak run --command=freecadcmd org.freecad.FreeCAD scripts/build_model.py
python3 scripts/dosing.py && python3 scripts/cook_energy.py && python3 scripts/residue.py
```
